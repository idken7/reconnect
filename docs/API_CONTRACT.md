# Reconnect API Contract (v1)

Single source of truth shared by the backend (`backend/`) and the Flutter app (`lib/`). Both sides implement exactly this. If something here is ambiguous, pick the simplest reading and note it in your final report; do not edit this file.

Base path `/v1`. JSON request and response bodies (`Content-Type: application/json`). Authenticated routes take `Authorization: Bearer <accessToken>`. Access tokens are opaque to the client.

## Errors

Every non-2xx response:

```json
{ "code": "snake_case_code", "error": "Human readable message", "requestId": "abc123" }
```

Rate limited requests return HTTP 429 with `code: "rate_limited"` plus `retryAfterSeconds` (int) and a `Retry-After` header. Malformed JSON, wrong types, or oversized bodies return 400 (`validation_error`) or 413 (`payload_too_large`), never 500.

| HTTP | code | meaning |
|------|------|---------|
| 400 | validation_error | bad input |
| 401 | missing_bearer_token, invalid_access_token, token_expired | access token problem. Client should try `/auth/refresh` once. |
| 401 | invalid_credentials | wrong email/password (same response for unknown email) |
| 401 | invalid_refresh_token, refresh_token_expired, refresh_token_reused | client must sign out and show login |
| 403 | verification_required | action needs a verified phone (e.g. importing contacts) |
| 409 | account_exists | email or phone already registered |
| 429 | rate_limited | see above |

## Auth

All auth-session responses share this shape (`SessionResponse`). `token` is a legacy alias of `accessToken`; keep it.

```json
{ "accessToken": "", "refreshToken": "", "accessTokenExpiresAt": "ISO8601", "token": "", "profile": { } }
```

| Route | Auth | Body | Response |
|-------|------|------|----------|
| POST `/auth/signup` | no | `{email, phone, password, name?, homeCity?, bio?}`. Password >= 8 chars and not in a common-password list. Phone is parsed to E.164 (default region US; accept `+` international). | SessionResponse. Sends a phone verification code. |
| POST `/auth/login` | no | `{email, password, deviceLabel?}` | SessionResponse. Does NOT invalidate the user's other sessions. |
| POST `/auth/refresh` | no | `{refreshToken}` | `{accessToken, refreshToken, accessTokenExpiresAt, token}`. Rotates the refresh token. Presenting an already-rotated token revokes that whole session (`refresh_token_reused`). |
| POST `/auth/logout` | yes | `{}` | `{ok:true}`. Revokes the session of the presented access token. |
| POST `/auth/logout-all` | yes | `{}` | `{ok:true}`. Revokes every session of the user. |
| POST `/auth/verify/phone/send` | yes | `{}` | `{ok:true}` |
| POST `/auth/verify/phone/confirm` | yes | `{code}` (6 digits) | `{profile}` |
| POST `/auth/verify/email/send` | yes | `{}` | `{ok:true}` |
| POST `/auth/verify/email/confirm` | yes | `{code}` | `{profile}` |
| POST `/auth/password-reset/request` | no | `{email}` | `{ok:true}` always (never reveals whether the account exists) |
| POST `/auth/password-reset/confirm` | no | `{email, code, newPassword}` | `{ok:true}`; revokes all sessions |

## Dashboard, contacts, location, profile

`GET /dashboard?location=` returns:

```json
{
  "profile": { },
  "supportedLocations": ["Brooklyn","Manhattan","Austin","Chicago","Other"],
  "currentLocation": "Brooklyn",
  "contactsImported": true,
  "contacts": [ContactObject],
  "suggestions": [ { "contact": ContactObject, "reason": "", "distanceLabel": "", "sharedLocations": [], "timeSinceLastSeen": "" } ]
}
```

`ContactObject`:

```json
{
  "id": "opaque id of the matched user",
  "name": "name from the viewer's own address book",
  "isOnApp": true,
  "mutual": true,
  "lastSeenAt": "ISO8601 or null",
  "availableIn": ["Brooklyn"],
  "preference": "loveToSee | neutral | ratherAvoid"
}
```

- `availableIn` is the matched user's current city and is present only if that user has `locationShared = true` AND the match is mutual; otherwise `[]`.
- The server never returns another user's email or phone, and never reveals `preference` to the other user.
- `timeSinceLastSeen` is a human string derived from `lastSeenAt` (e.g. "2 weeks ago", "Unknown").

| Route | Auth | Body | Response |
|-------|------|------|----------|
| POST `/contacts/import` | yes, phone verified (else 403 `verification_required`) | `{contacts:[{name, phones:[string], emails:[string]}], location?}` max 5000 contacts, 5 MB. Plain values over TLS; the server normalizes and stores only an HMAC (server pepper) of each identifier plus the display name. | dashboard |
| GET `/contacts/matches` | yes | | `{mutual:[ContactObject], oneWay:[ContactObject], notOnApp:[{name, status:"notOnApp"}]}` |
| PATCH `/contacts/{id}/preference` | yes | `{preference}` (enum above) | dashboard |
| PATCH `/location` | yes | `{location}` (one of supportedLocations) or `{latitude, longitude}` | dashboard. Unknown coordinates map to `"Other"`, never a default city. |
| PATCH `/profile` | yes | `{bio?, homeCity?, profileImageUrl?, locationShared?}` profileImageUrl must be `https://` or empty. | dashboard |

Matching rules (server): "on app" = the imported identifier equals a verified phone or verified email of another user. `mutual` = that user has also imported an identifier of the viewer. `oneWay` = viewer has them, they do not have the viewer. A user with no verified identifier is never matchable.

## Operational endpoints

`GET /health` -> `{status:"ok"}` (liveness). `GET /ready` -> `{status:"ok"}` or 503 if the database is unreachable.

## Verification delivery

Server env `VERIFICATION_PROVIDER` = `console` (logs the code; default for non-production) or `twilio` (Twilio Verify for phone, SMTP/console for email). When `ENV != production` and `VERIFICATION_PROVIDER=console`, the code `000000` is always accepted so tests and local development work. In `production` this shortcut must be impossible.
